# Визуализатор графа зависимостей пакетов NuGet (Вариант 23)

## 1. Общее описание
Консольное (CLI) приложение для построения и визуализации графа зависимостей пакетов менеджера пакетов .NET (NuGet). Готовые менеджеры пакетов и библиотеки для получения зависимостей не используются: данные загружаются напрямую из репозитория NuGet по протоколу HTTP и разбираются средствами стандартной библиотеки Python. Изображение графа строится программой Graphviz по описанию на языке DOT, которое формирует приложение.

Проект написан на языке Python 3.12 с использованием только стандартной библиотеки в рамках практической работы по дисциплине «Конфигурационное управление».

**Этап 1.** Минимальный прототип с конфигурацией: параметры командной строки и их проверка.

**Этап 2.** Сбор данных: получение прямых зависимостей пакета из репозитория NuGet по URL-адресу.

**Этап 3.** Основные операции: построение графа зависимостей с учетом транзитивности алгоритмом DFS с рекурсией, ограничение максимальной глубины, обработка циклических зависимостей, режим тестового репозитория.

**Этап 4.** Дополнительные операции: режим вывода обратных зависимостей (по заданию — только для этапа 4, на этапе 5 убран).

**Этап 5 (текущий).** Визуализация: описание графа на языке диаграмм Graphviz, изображение графа в формате SVG, вывод зависимостей в виде ASCII-дерева, сравнение со штатными инструментами NuGet.

## 2. Описание всех функций и настроек

### Параметры командной строки

| Параметр | Описание | По умолчанию |
|---|---|---|
| `-p`, `--package <имя>` | Имя анализируемого пакета. | обязательный |
| `-r`, `--repo <url или путь>` | URL-адрес репозитория (индекс сервиса NuGet V3, например `https://api.nuget.org/v3/index.json`) или путь к файлу тестового репозитория. | обязательный |
| `-t`, `--test-mode` | Режим работы с тестовым репозиторием: в `--repo` указывается путь к файлу описания графа. | выключен |
| `-o`, `--output <файл>` | Имя сгенерированного файла с изображением графа (`.svg`). | `graph.svg` |
| `-a`, `--ascii-tree` | Режим вывода зависимостей в формате ASCII-дерева. | выключен |
| `-d`, `--max-depth <число>` | Максимальная глубина анализа зависимостей. | `3` |
| `-h`, `--help` | Справка по параметрам. | — |

### Порядок работы
1. Проверка параметров.
2. Построение графа зависимостей (из NuGet или тестового репозитория) и вывод графа на экран.
3. Вывод описания графа на языке Graphviz.
4. Если задан `--ascii-tree` — вывод ASCII-дерева зависимостей.
5. Сохранение изображения графа в файл SVG (`--output`) с помощью Graphviz.

### Получение прямых зависимостей из NuGet
1. Загружается индекс сервиса NuGet V3 по URL-адресу из `--repo` (JSON) и в нем находится ресурс `PackageBaseAddress/3.0.0` — адрес хранилища пакетов.
2. Загружается список версий пакета: `<хранилище>/<имя пакета>/index.json`.
3. Выбирается последняя стабильная версия (без суффикса вида `-beta`). Если стабильных версий нет, берется последняя.
4. Загружается файл описания пакета `.nuspec` (XML): `<хранилище>/<имя>/<версия>/<имя>.nuspec`.
5. Из элементов `<dependency>` извлекаются имена прямых зависимостей. Зависимости из групп для разных платформ (`<group targetFramework="...">`) объединяются без повторов.

Имя пакета не зависит от регистра. Зависимости каждого пакета загружаются один раз (кэш). При сбое сети запрос повторяется до 3 раз. Для каждой зависимости берется ее последняя стабильная версия, а не версия из диапазона, указанного в `.nuspec`.

### Построение графа (DFS)
Граф строится рекурсивным обходом в глубину (функция `visit()`), начиная с заданного пакета (глубина 0):
* **Транзитивность.** Для каждой зависимости рекурсивно запрашиваются ее зависимости.
* **Максимальная глубина.** Зависимости раскрываются только у пакетов на глубине меньше `--max-depth`. Пакеты на максимальной глубине попадают в граф, но их зависимости не анализируются. Если пакет встречается на разной глубине, он раскрывается по самому короткому пути.
* **Общие зависимости.** Пакет, от которого зависят несколько пакетов, анализируется один раз.
* **Циклические зависимости.** Во время обхода хранится текущий путь от корня. Если зависимость уже есть в этом пути, найден цикл: он запоминается (без повторов), а обход по этой ветке останавливается. Зависимость пакета от самого себя тоже считается циклом.
* **Проверка итогового графа.** После обхода построенный граф еще раз обходится в глубину (функция `collect_cycles()`), чтобы найти циклы, которые видны в итоговом графе, но при обходе не лежали на одном пути.

### Описание графа на языке Graphviz
Функция `make_dot()` формирует описание графа на языке DOT:
```text
digraph "A" {
    node [shape=box];
    "A" [style=filled, fillcolor=lightblue];
    "A" -> "B";
    "D" [style=dashed];
    "E" -> "E" [color=red];
}
```
* каждый пакет — прямоугольник, каждая зависимость — стрелка `пакет -> зависимость`;
* анализируемый пакет закрашен голубым;
* пакеты, которые не анализировались из-за ограничения глубины, обведены пунктиром;
* стрелки, входящие в циклические зависимости, красные.

### Изображение графа (SVG)
Функция `save_svg()` передает описание графа программе Graphviz (`dot -Tsvg -o <файл>`), которая строит изображение и сохраняет его в файл из параметра `--output`. Файл можно открыть в браузере. Сгенерированные файлы `.svg` не хранятся в репозитории (указаны в `.gitignore`).

Если Graphviz не установлен, выводится сообщение `Ошибка: программа Graphviz (dot) не найдена ...` и приложение завершается с кодом `1`.

### ASCII-дерево (параметр `--ascii-tree`)
Зависимости выводятся деревом из символов ASCII, начиная с анализируемого пакета:
```text
A
|-- B
|   `-- C
|       |-- A (цикл)
|       `-- E
|           `-- E (цикл)
`-- D
    `-- E (см. выше)
```
Пометки:
* `(цикл)` — пакет уже есть выше на этой ветке, дальше ветка не раскрывается;
* `(не анализировался)` — достигнута максимальная глубина;
* `(см. выше)` — зависимости этого пакета уже выведены выше, повторно ветка не раскрывается.

### Тестовый репозиторий
Текстовый файл (UTF-8) с описанием графа, пакеты называются большими латинскими буквами. Каждая строка описывает один пакет и его прямые зависимости:
```text
# комментарий
A: B C
B: D
D:
```
* Текст после `#` — комментарий, пустые строки пропускаются.
* Пакет, который указан только как зависимость, считается пакетом без зависимостей.
* Ошибки: строка без `:`, имя не из больших латинских букв, повторное описание пакета, файл не найден, анализируемого пакета нет в репозитории.

Готовые тестовые репозитории в папке `repos/`:
* `test_repo.txt` — общая зависимость (A -> B, C; B и C -> D);
* `cycle.txt` — цикл A -> B -> C -> A и зависимость E от самого себя;
* `chain.txt` — цепочка A -> B -> C -> D -> E -> F для проверки максимальной глубины;
* `invalid.txt` — файл с ошибкой для проверки обработки ошибок.

### Обработка ошибок
Все параметры проверяются перед запуском. Если найдены ошибки, выводятся **все** ошибки (по одной на строку, с префиксом `Ошибка:` и именем параметра), а приложение завершается с кодом `1`.

| Параметр | Ошибки |
|---|---|
| `--package` | имя не задано; длиннее 100 символов; содержит символы, кроме латинских букв, цифр и `.` `_` `-` |
| `--repo` | не задан; без `--test-mode` — не является URL-адресом с `http://` или `https://`; с `--test-mode` — файл не найден |
| `--output` | пустое имя файла; недопустимые символы `<>:"\|?*`; расширение не `.svg`; указанная папка не существует |
| `--max-depth` | не целое число; меньше `1` |

Ошибки при построении и визуализации графа (код завершения `1`):
* сервер недоступен (`не удалось подключиться к ...`);
* по URL-адресу нет индекса сервиса, ответ не является JSON или в индексе нет ресурса `PackageBaseAddress/3.0.0`;
* пакет отсутствует в репозитории (`пакет '...' не найден в репозитории`);
* у пакета нет версий, некорректный файл `.nuspec`, другие ошибки сервера;
* ошибки тестового репозитория (см. выше);
* Graphviz не установлен или завершился с ошибкой.

### Функции
* `parse_args()` — разбор параметров командной строки (`argparse`).
* `validate_package()`, `validate_repo()`, `validate_output()`, `validate_max_depth()`, `validate_args()` — проверка параметров.
* `fetch_once()`, `fetch()`, `fetch_json()` — загрузка данных по URL-адресу (`urllib`), с повтором при сбое сети.
* `find_package_base()`, `get_versions()`, `select_version()`, `parse_dependencies()` — работа с репозиторием NuGet и разбор `.nuspec` (`xml.etree.ElementTree`).
* `make_nuget_resolver()` — функция получения зависимостей пакета из NuGet (с кэшем).
* `parse_test_line()`, `load_test_repo()`, `make_test_resolver()` — загрузка тестового репозитория и функция получения зависимостей из него.
* `visit()` — рекурсивный обход в глубину (DFS); `add_cycle()` — запоминание цикла без повторов; `collect_cycles()` — поиск циклов в построенном графе.
* `build_graph()` — построение графа `DependencyGraph`.
* `print_graph()` — вывод графа и циклов.
* `quote()`, `make_dot()` — описание графа на языке Graphviz.
* `save_svg()` — сохранение изображения графа в SVG с помощью Graphviz (`subprocess`).
* `tree_note()`, `print_tree_children()`, `print_ascii_tree()` — вывод ASCII-дерева.
* `visualize()` — вывод описания Graphviz, ASCII-дерева и сохранение SVG.
* `main()` — точка входа, возвращает код завершения.

## 3. Описание команд для сборки проекта и запуска тестов

### Сборка и зависимости
Используется только стандартная библиотека Python, установка пакетов Python не требуется. Для работы с реальным репозиторием NuGet нужен доступ в интернет.

Для сохранения изображения графа нужна программа **Graphviz**: установщик для Windows — на странице https://graphviz.org/download/ (при установке выбрать добавление Graphviz в переменную PATH). Проверка установки:
```bash
dot -V
```

Для изоляции можно создать виртуальное окружение:
```bash
python -m venv .venv
```

### Запуск
```bash
python src/main.py --package Polly --repo https://api.nuget.org/v3/index.json --max-depth 3 --output polly.svg --ascii-tree
python src/main.py --package A --repo repos/cycle.txt --test-mode --output cycle.svg --ascii-tree
```

Скрипты для Windows в папке `scripts/` (запускаются из корня проекта):
* `scripts\run.bat` — граф пакета `Polly` из реального репозитория NuGet со всеми параметрами (изображение `polly.svg`);
* `scripts\run_visualize.bat` — визуализация трех различных пакетов NuGet (`polly.svg`, `serilog.svg`, `xunit.svg`) и графа тестового репозитория с циклами (`cycle.svg`);
* `scripts\run_packages.bat` — графы нескольких пакетов NuGet с разной глубиной;
* `scripts\run_test_mode.bat` — различные случаи работы с тестовым репозиторием: общая зависимость, циклы, разная максимальная глубина, ошибки;
* `scripts\run_errors.bat` — демонстрация обработки ошибок.

### Запуск тестов
Тесты не обращаются к сети и не вызывают Graphviz: ответы репозитория и вызов Graphviz подменяются.
```bash
python -m unittest discover -s tests
```

## 5. Сравнение со штатными инструментами NuGet
Штатные средства просмотра зависимостей NuGet:
* вкладка **Dependencies** на странице пакета на сайте nuget.org — прямые зависимости пакета отдельно для каждой целевой платформы (`net8.0`, `.NETStandard 2.0`, `.NETFramework 4.6.2` и т. д.);
* команда `dotnet list package --include-transitive` в проекте .NET и менеджер пакетов NuGet в Visual Studio — список пакетов (прямых и транзитивных), реально подключенных к проекту для его целевой платформы.

Прямые зависимости пакета совпадают с вкладкой Dependencies на nuget.org: и сайт, и приложение берут их из одного и того же файла `.nuspec`. Различия в итоговом графе и их причины:

1. **Целевая платформа.** Штатные инструменты показывают зависимости для конкретной платформы, а приложение объединяет группы всех платформ. Пример: у `Serilog 4.4.0` для `net6.0`, `net8.0`, `net9.0`, `net10.0` зависимостей нет, для `.NETStandard 2.0` их две (`System.Diagnostics.DiagnosticSource`, `System.Threading.Channels`), для `.NETFramework 4.6.2` — три (добавляется `System.ValueTuple`). Приложение показывает все три, поэтому граф больше, чем у проекта на `net8.0`, где `dotnet list package` не покажет ни одной зависимости Serilog. Аналогично у `Polly.Core 8.9.0`: для `net8.0` зависимостей нет, для `.NETStandard 2.0` — четыре, для `.NETFramework 4.6.2` — пять.
2. **Версии транзитивных зависимостей.** В `.nuspec` указывается минимальная версия зависимости (например, `System.Threading.Tasks.Extensions 4.5.4`), и NuGet при установке выбирает минимальную подходящую версию — 4.5.4. Приложение для каждой зависимости берет ее последнюю стабильную версию (4.6.3), а у разных версий зависимости могут отличаться: версия 4.5.4 для `.NETStandard 1.0` зависит еще от `System.Collections`, `System.Runtime`, `System.Threading.Tasks`, а версия 4.6.3 — только от `System.Runtime.CompilerServices.Unsafe`. Поэтому транзитивная часть графа может отличаться от того, что установит NuGet.
3. **Максимальная глубина.** Приложение анализирует зависимости до глубины `--max-depth`, а `dotnet list package --include-transitive` показывает все транзитивные зависимости без ограничения.
4. **Форма вывода.** nuget.org показывает только прямые зависимости, `dotnet list package` — плоский список пакетов без связей между ними. Приложение показывает структуру графа (кто от кого зависит), общие зависимости и циклы.
5. **Актуальность.** Приложение берет последнюю версию пакета на момент запуска, поэтому со временем результат меняется (при подготовке примеров `Polly` обновился с 8.8.0 до 8.9.0).
