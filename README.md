# Визуализатор графа зависимостей пакетов NuGet (Вариант 23)

## 1. Общее описание
Консольное (CLI) приложение для построения и визуализации графа зависимостей пакетов менеджера пакетов .NET (NuGet). Готовые менеджеры пакетов и библиотеки для получения зависимостей не используются: данные загружаются напрямую из репозитория NuGet по протоколу HTTP и разбираются средствами стандартной библиотеки Python.

Проект написан на языке Python 3.12 с использованием только стандартной библиотеки в рамках практической работы по дисциплине «Конфигурационное управление».

**Этап 1.** Минимальный прототип с конфигурацией: параметры командной строки и их проверка.

**Этап 2 (текущий).** Сбор данных: получение прямых зависимостей заданного пакета из репозитория NuGet по URL-адресу и вывод их на экран.

## 2. Описание всех функций и настроек

### Параметры командной строки

| Параметр | Описание | По умолчанию |
|---|---|---|
| `-p`, `--package <имя>` | Имя анализируемого пакета. | обязательный |
| `-r`, `--repo <url или путь>` | URL-адрес репозитория (индекс сервиса NuGet V3, например `https://api.nuget.org/v3/index.json`) или путь к файлу тестового репозитория. | обязательный |
| `-t`, `--test-mode` | Режим работы с тестовым репозиторием: в `--repo` указывается путь к файлу. На этапе 2 получение зависимостей из тестового репозитория еще не поддерживается. | выключен |
| `-o`, `--output <файл>` | Имя сгенерированного файла с изображением графа (`.svg`). | `graph.svg` |
| `-a`, `--ascii-tree` | Режим вывода зависимостей в формате ASCII-дерева. | выключен |
| `-d`, `--max-depth <число>` | Максимальная глубина анализа зависимостей. | `3` |
| `-h`, `--help` | Справка по параметрам. | — |

### Получение прямых зависимостей (формат пакетов NuGet)
1. Загружается индекс сервиса NuGet V3 по URL-адресу из `--repo` (JSON) и в нем находится ресурс `PackageBaseAddress/3.0.0` — адрес хранилища пакетов.
2. Загружается список версий пакета: `<хранилище>/<имя пакета>/index.json`.
3. Выбирается последняя стабильная версия (без суффикса вида `-beta`). Если стабильных версий нет, берется последняя.
4. Загружается файл описания пакета `.nuspec` (XML): `<хранилище>/<имя>/<версия>/<имя>.nuspec`.
5. Из элементов `<dependency>` извлекаются имена и версии прямых зависимостей. Зависимости из групп для разных платформ (`<group targetFramework="...">`) объединяются без повторов и сортируются по имени.

Имя пакета не зависит от регистра (`newtonsoft.json` и `Newtonsoft.Json` — один и тот же пакет).

Вывод:
```text
Пакет: <имя> <версия>
Прямые зависимости (<количество>):
  <зависимость> <версия>
```
Если зависимостей нет, выводится `Прямые зависимости: нет`.

### Обработка ошибок
Все параметры проверяются перед запуском. Если найдены ошибки, выводятся **все** ошибки (по одной на строку, с префиксом `Ошибка:` и именем параметра), а приложение завершается с кодом `1`.

| Параметр | Ошибки |
|---|---|
| `--package` | имя не задано; длиннее 100 символов; содержит символы, кроме латинских букв, цифр и `.` `_` `-` |
| `--repo` | не задан; без `--test-mode` — не является URL-адресом с `http://` или `https://`; с `--test-mode` — файл не найден |
| `--test-mode` | на этапе 2 получение зависимостей из тестового репозитория не поддерживается |
| `--output` | пустое имя файла; недопустимые символы `<>:"\|?*`; расширение не `.svg`; указанная папка не существует |
| `--max-depth` | не целое число; меньше `1` |

Ошибки при получении данных из репозитория (код завершения `1`):
* сервер недоступен (`не удалось подключиться к ...`);
* по URL-адресу нет индекса сервиса (`индекс сервиса NuGet не найден по адресу ...`);
* ответ не является JSON или в индексе нет ресурса `PackageBaseAddress/3.0.0`;
* пакет отсутствует в репозитории (`пакет '...' не найден в репозитории`);
* у пакета нет версий, некорректный файл `.nuspec`, другие ошибки сервера.

### Функции
* `parse_args()` — разбор параметров командной строки (`argparse`).
* `validate_package()`, `validate_repo()`, `validate_output()`, `validate_max_depth()` — проверка отдельных параметров, возвращают текст ошибки или `None`.
* `validate_args()` — проверка всех параметров, возвращает список ошибок.
* `fetch()`, `fetch_json()` — загрузка данных и JSON по URL-адресу (`urllib`).
* `find_package_base()` — поиск адреса хранилища пакетов в индексе сервиса.
* `get_versions()`, `select_version()` — получение списка версий и выбор версии.
* `parse_dependencies()` — разбор файла `.nuspec` (`xml.etree.ElementTree`).
* `get_direct_dependencies()` — получение версии пакета и его прямых зависимостей.
* `print_dependencies()` — вывод прямых зависимостей.
* `main()` — точка входа, возвращает код завершения.

### Тестовый репозиторий
Файл `repos/test_repo.txt` — пример файла тестового репозитория для режима `--test-mode`. Пакеты в нем называются большими латинскими буквами.

## 3. Описание команд для сборки проекта и запуска тестов

### Сборка и зависимости
Используется только стандартная библиотека Python, установка сторонних пакетов не требуется. Для получения зависимостей нужен доступ в интернет. Для изоляции можно создать виртуальное окружение:
```bash
python -m venv .venv
```

### Запуск
```bash
python src/main.py --package Newtonsoft.Json --repo https://api.nuget.org/v3/index.json
```

Скрипты для Windows в папке `scripts/` (запускаются из корня проекта):
* `scripts\run.bat` — прямые зависимости пакета `Newtonsoft.Json` (со всеми параметрами);
* `scripts\run_packages.bat` — прямые зависимости нескольких пакетов: с несколькими зависимостями, с одной, без зависимостей, имя в другом регистре;
* `scripts\run_test_mode.bat` — запуск в режиме тестового репозитория (на этапе 2 выводит сообщение о том, что режим не поддерживается);
* `scripts\run_errors.bat` — демонстрация обработки ошибок для всех параметров и ошибок получения данных.

### Запуск тестов
Тесты не обращаются к сети: ответы репозитория подменяются тестовыми данными.
```bash
python -m unittest discover -s tests
```

### Прямые зависимости пакета
```text
> python src/main.py -p Newtonsoft.Json -r https://api.nuget.org/v3/index.json

Прямые зависимости (6):
  Microsoft.CSharp 4.3.0
  NETStandard.Library 1.6.1
  System.ComponentModel.TypeConverter 4.3.0
  System.Runtime.Serialization.Formatters 4.3.0
  System.Runtime.Serialization.Primitives 4.3.0
  System.Xml.XmlDocument 4.3.0

> python src/main.py -p Polly -r https://api.nuget.org/v3/index.json
Пакет: Polly 8.8.0
Прямые зависимости (1):
  Polly.Core 8.8.0

> python src/main.py -p System.ValueTuple -r https://api.nuget.org/v3/index.json
Пакет: System.ValueTuple 4.6.2
Прямые зависимости: нет
```
Номера версий соответствуют состоянию репозитория NuGet на момент запуска и со временем могут меняться.

### Обработка ошибок
```text
> python src/main.py
Ошибка: не задано имя пакета (--package)
Ошибка: не задан URL-адрес или путь к репозиторию (--repo)

> python src/main.py --package "bad name!" --repo nuget --output graph.png --max-depth -5
Ошибка: недопустимое имя пакета 'bad name!': разрешены латинские буквы, цифры и символы . _ - (--package)
Ошибка: некорректный URL-адрес репозитория 'nuget': ожидается адрес вида https://... (для файла укажите --test-mode)
Ошибка: файл с изображением графа должен иметь расширение .svg: 'graph.png' (--output)
Ошибка: максимальная глубина должна быть не меньше 1, получено -5 (--max-depth)

> python src/main.py -p NoSuchPackageXyz123 -r https://api.nuget.org/v3/index.json
Ошибка: пакет 'NoSuchPackageXyz123' не найден в репозитории

> python src/main.py -p Serilog -r https://example.com/
Ошибка: ответ https://example.com/ не является JSON
```
