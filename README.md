# Визуализатор графа зависимостей пакетов NuGet (Вариант 23)

## 1. Общее описание
Консольное (CLI) приложение для построения и визуализации графа зависимостей пакетов менеджера пакетов .NET (NuGet). Готовые менеджеры пакетов и библиотеки для получения зависимостей не используются: данные загружаются напрямую из репозитория NuGet по протоколу HTTP и разбираются средствами стандартной библиотеки Python.

Проект написан на языке Python 3.12 с использованием только стандартной библиотеки в рамках практической работы по дисциплине «Конфигурационное управление».

**Этап 1.** Минимальный прототип с конфигурацией: параметры командной строки и их проверка.

**Этап 2.** Сбор данных: получение прямых зависимостей пакета из репозитория NuGet по URL-адресу.

**Этап 3.** Основные операции: построение графа зависимостей с учетом транзитивности алгоритмом DFS с рекурсией, ограничение максимальной глубины, обработка циклических зависимостей, режим тестового репозитория.

**Этап 4 (текущий).** Дополнительные операции: режим вывода обратных зависимостей — пакетов, которые зависят от заданного пакета.

## 2. Описание всех функций и настроек

### Параметры командной строки

| Параметр | Описание | По умолчанию |
|---|---|---|
| `-p`, `--package <имя>` | Имя анализируемого пакета. | обязательный |
| `-r`, `--repo <url или путь>` | URL-адрес репозитория (индекс сервиса NuGet V3, например `https://api.nuget.org/v3/index.json`) или путь к файлу тестового репозитория. | обязательный |
| `-t`, `--test-mode` | Режим работы с тестовым репозиторием: в `--repo` указывается путь к файлу описания графа. | выключен |
| `-o`, `--output <файл>` | Имя сгенерированного файла с изображением графа (`.svg`). | `graph.svg` |
| `-a`, `--ascii-tree` | Режим вывода зависимостей в формате ASCII-дерева. | выключен |
| `-d`, `--max-depth <число>` | Максимальная глубина анализа зависимостей. | `3` |
| `-R`, `--reverse` | Режим вывода обратных зависимостей: пакетов, которые зависят от заданного пакета. Работает только с `--test-mode`. | выключен |
| `-h`, `--help` | Справка по параметрам. | — |

Параметры `--output` и `--ascii-tree` проверяются при запуске и используются на этапе визуализации.

### Получение прямых зависимостей из NuGet
1. Загружается индекс сервиса NuGet V3 по URL-адресу из `--repo` (JSON) и в нем находится ресурс `PackageBaseAddress/3.0.0` — адрес хранилища пакетов.
2. Загружается список версий пакета: `<хранилище>/<имя пакета>/index.json`.
3. Выбирается последняя стабильная версия (без суффикса вида `-beta`). Если стабильных версий нет, берется последняя.
4. Загружается файл описания пакета `.nuspec` (XML): `<хранилище>/<имя>/<версия>/<имя>.nuspec`.
5. Из элементов `<dependency>` извлекаются имена прямых зависимостей. Зависимости из групп для разных платформ (`<group targetFramework="...">`) объединяются без повторов.

Имя пакета не зависит от регистра. Зависимости каждого пакета загружаются один раз (кэш). При сбое сети запрос повторяется до 3 раз.

Для каждой зависимости берется ее последняя стабильная версия, а не версия из диапазона, указанного в `.nuspec`.

### Построение графа (DFS)
Граф строится рекурсивным обходом в глубину (функция `visit()`), начиная с заданного пакета (глубина 0):
* **Транзитивность.** Для каждой зависимости рекурсивно запрашиваются ее зависимости.
* **Максимальная глубина.** Зависимости раскрываются только у пакетов на глубине меньше `--max-depth`. Пакеты на максимальной глубине попадают в граф, но их зависимости не анализируются (`не анализировался (достигнута максимальная глубина)`). Если пакет встречается на разной глубине, он раскрывается по самому короткому пути.
* **Общие зависимости.** Пакет, от которого зависят несколько пакетов, анализируется один раз.
* **Циклические зависимости.** Во время обхода хранится текущий путь от корня. Если зависимость уже есть в этом пути, найден цикл: он запоминается (без повторов), а обход по этой ветке останавливается. Поэтому программа не зацикливается. Зависимость пакета от самого себя тоже считается циклом.
* **Проверка итогового графа.** После обхода построенный граф еще раз обходится в глубину (функция `collect_cycles()`), чтобы найти циклы, которые видны в итоговом графе, но при обходе не лежали на одном пути (например, когда пакет сначала попал на границу глубины, а потом был раскрыт по более короткому пути).

Вывод:
```text
Граф зависимостей пакета <имя> (максимальная глубина: <число>)
  <пакет> -> <зависимости через запятую | нет | не анализировался (...)>
Пакетов в графе: <количество>
Циклические зависимости: нет | (<количество>): <цикл>
```

### Обратные зависимости (параметр `--reverse`)
Обратные зависимости пакета — это пакеты, которые от него зависят: напрямую и транзитивно (через другие пакеты).

1. Граф тестового репозитория «переворачивается» (функция `reverse_repo()`): для каждого пакета составляется список пакетов, в описании которых он указан как зависимость. Например, из `A: B C` и `B: C` получается `B <- A`, `C <- A, B`.
2. По перевернутому графу запускается тот же алгоритм обхода в глубину, что и для прямых зависимостей (`build_graph()` и `visit()`), поэтому так же учитываются максимальная глубина и циклические зависимости.

Режим работает только с тестовым репозиторием: для реального репозитория NuGet пришлось бы загрузить описания всех пакетов репозитория, а готового способа получить список пакетов, зависящих от заданного, протокол NuGet V3 не предоставляет.

Вывод:
```text
Обратные зависимости пакета <имя> (максимальная глубина: <число>)
  <пакет> <- <пакеты, которые от него зависят | нет | не анализировался (...)>
Пакетов, зависящих от <имя>: <количество>
Циклические зависимости: нет | (<количество>): <цикл>
```
Запись `D <- B, C` означает, что пакеты `B` и `C` зависят от пакета `D`.

### Тестовый репозиторий
Текстовый файл (UTF-8) с описанием графа, пакеты называются большими латинскими буквами. Каждая строка описывает один пакет и его прямые зависимости:
```text
# комментарий
A: B C
B: D
D:
```
* Текст после `#` — комментарий, пустые строки пропускаются.
* Пакет, который указан только как зависимость, считается пакетом без зависимостей.
* Ошибки: строка без `:`, имя не из больших латинских букв, повторное описание пакета, файл не найден, анализируемого пакета нет в репозитории.

Готовые тестовые репозитории в папке `repos/`:
* `test_repo.txt` — общая зависимость (A -> B, C; B и C -> D);
* `cycle.txt` — цикл A -> B -> C -> A и зависимость E от самого себя;
* `chain.txt` — цепочка A -> B -> C -> D -> E -> F для проверки максимальной глубины;
* `library.txt` — библиотека L, от которой зависят B, D, E напрямую и A, C, F, G транзитивно (для обратных зависимостей);
* `invalid.txt` — файл с ошибкой для проверки обработки ошибок.

### Обработка ошибок
Все параметры проверяются перед запуском. Если найдены ошибки, выводятся **все** ошибки (по одной на строку, с префиксом `Ошибка:` и именем параметра), а приложение завершается с кодом `1`.

| Параметр | Ошибки |
|---|---|
| `--package` | имя не задано; длиннее 100 символов; содержит символы, кроме латинских букв, цифр и `.` `_` `-` |
| `--repo` | не задан; без `--test-mode` — не является URL-адресом с `http://` или `https://`; с `--test-mode` — файл не найден |
| `--output` | пустое имя файла; недопустимые символы `<>:"\|?*`; расширение не `.svg`; указанная папка не существует |
| `--max-depth` | не целое число; меньше `1` |
| `--reverse` | указан без `--test-mode` |

Ошибки при построении графа (код завершения `1`):
* сервер недоступен (`не удалось подключиться к ...`);
* по URL-адресу нет индекса сервиса, ответ не является JSON или в индексе нет ресурса `PackageBaseAddress/3.0.0`;
* пакет отсутствует в репозитории (`пакет '...' не найден в репозитории`);
* у пакета нет версий, некорректный файл `.nuspec`, другие ошибки сервера;
* ошибки тестового репозитория (см. выше).

### Функции
* `parse_args()` — разбор параметров командной строки (`argparse`).
* `validate_package()`, `validate_repo()`, `validate_output()`, `validate_max_depth()`, `validate_reverse()`, `validate_args()` — проверка параметров.
* `fetch_once()`, `fetch()`, `fetch_json()` — загрузка данных по URL-адресу (`urllib`), с повтором при сбое сети.
* `find_package_base()`, `get_versions()`, `select_version()`, `parse_dependencies()` — работа с репозиторием NuGet и разбор `.nuspec` (`xml.etree.ElementTree`).
* `make_nuget_resolver()` — функция получения зависимостей пакета из NuGet (с кэшем).
* `parse_test_line()`, `load_test_repo()`, `make_test_resolver()` — загрузка тестового репозитория и функция получения зависимостей из него (прямых или обратных).
* `reverse_repo()` — переворот графа для поиска обратных зависимостей.
* `visit()` — рекурсивный обход в глубину (DFS); `add_cycle()` — запоминание цикла без повторов.
* `collect_cycles()` — поиск циклов в построенном графе.
* `build_graph()` — построение графа `DependencyGraph`.
* `print_graph()` — вывод графа (или обратных зависимостей) и циклов.
* `main()` — точка входа, возвращает код завершения.

## 3. Описание команд для сборки проекта и запуска тестов

### Сборка и зависимости
Используется только стандартная библиотека Python, установка сторонних пакетов не требуется. Для работы с реальным репозиторием NuGet нужен доступ в интернет. Для изоляции можно создать виртуальное окружение:
```bash
python -m venv .venv
```

### Запуск
```bash
python src/main.py --package Polly --repo https://api.nuget.org/v3/index.json --max-depth 3
python src/main.py --package A --repo repos/cycle.txt --test-mode
python src/main.py --package L --repo repos/library.txt --test-mode --reverse
```

Скрипты для Windows в папке `scripts/` (запускаются из корня проекта):
* `scripts\run.bat` — граф пакета `Polly` из реального репозитория NuGet (со всеми параметрами);
* `scripts\run_packages.bat` — графы нескольких пакетов NuGet с разной глубиной;
* `scripts\run_test_mode.bat` — различные случаи работы с тестовым репозиторием: общая зависимость, циклы, разная максимальная глубина, ошибки;
* `scripts\run_reverse.bat` — различные случаи вывода обратных зависимостей в тестовом репозитории: общая зависимость, прямые и транзитивные зависимости, разная глубина, пакет без обратных зависимостей, циклы, ошибки;
* `scripts\run_errors.bat` — демонстрация обработки ошибок.

### Запуск тестов
Тесты не обращаются к сети: ответы репозитория подменяются тестовыми данными.
```bash
python -m unittest discover -s tests
```
